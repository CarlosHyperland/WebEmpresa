1. Resumen ejecutivo

Se realizó un escaneo de la API local ApiClientes con OWASP ZAP. En el informe inicial se identificó una alerta de riesgo bajo por la ausencia de la cabecera HTTP X-Content-Type-Options. Se modificó Program.cs para enviar la cabecera X-Content-Type-Options: nosniff.

La verificación manual posterior con curl devolvió HTTP/1.1 200 OK y mostró la cabecera esperada. El informe posterior de ZAP declara: “No alerts were found within the report parameters.” Esto indica que el reporte posterior no contiene alertas dentro de los parámetros seleccionados.

4. Hallazgo inicial

X-Content-Type-Options Header Missing Riesgo bajo

En el informe inicial, ZAP señaló que la respuesta a GET http://localhost:5081/api/Clientes no incluía la cabecera X-Content-Type-Options. La recomendación consiste en enviar el valor nosniff, que indica a los navegadores que no deben intentar adivinar o reinterpretar el tipo MIME de la respuesta.

La alerta fue clasificada por ZAP con confianza media. Su presencia no significaba que se hubiera demostrado una explotación, sino que faltaba una medida de endurecimiento de la respuesta HTTP.

5. Corrección aplicada

Se añadió un middleware en Program.cs, después de construir la aplicación y antes de mapear los controladores:

app.Use(async (context, next) =>
{
    context.Response.Headers["X-Content-Type-Options"] = "nosniff";
    await next();
});

Este middleware añade la cabecera a las respuestas que pasan por esa parte del pipeline. La ubicación concreta debe mantenerse antes de app.MapControllers().

7. Limitaciones

  • El reporte posterior no contiene alertas, pero eso no demuestra que la API esté libre de todas las vulnerabilidades.
  • La prueba manual mostrada cubre el endpoint GET /api/Clientes; no demuestra el comportamiento de todas las rutas, métodos HTTP o respuestas de error.
  • No se aportó evidencia de pruebas exhaustivas de autenticación, autorización, validación de entradas, control de acceso a clientes ni operaciones de creación, modificación y eliminación.
  • El escaneo automatizado depende de las rutas que ZAP pudo descubrir y de los parámetros configurados.
  • Las advertencias de paquetes NuGet y de redirección HTTPS observadas al ejecutar la API son asuntos separados de la alerta de cabecera y no quedan resueltos por este cambio.

8. Recomendaciones

  1. Mantener la cabecera X-Content-Type-Options: nosniff y verificarla en las respuestas relevantes.
  2. Revisar por separado las advertencias de paquetes NuGet con vulnerabilidades conocidas y actualizar las dependencias a versiones compatibles y corregidas, después de comprobar compatibilidad.
  3. Configurar HTTPS correctamente para los entornos donde corresponda; la advertencia de que ASP.NET Core no pudo determinar el puerto HTTPS es independiente de esta cabecera.
  4. Probar de forma controlada las rutas y métodos autorizados, especialmente autenticación, autorización y operaciones que modifican datos. Usar una base de datos de pruebas o una copia de seguridad antes de realizar escaneos activos.

9. Conclusión

La comparación de los informes muestra que la alerta inicial de riesgo bajo por ausencia de X-Content-Type-Options ya no aparece en el reporte posterior. La comprobación con curl confirma que la API envía X-Content-Type-Options: nosniff en la respuesta de prueba. Por tanto, la corrección de esta cabecera queda verificada para esa solicitud. Se recomienda continuar con pruebas adicionales y revisar por separado las demás advertencias de configuración y dependencias.
