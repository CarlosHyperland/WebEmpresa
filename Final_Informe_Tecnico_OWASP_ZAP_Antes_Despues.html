4. Hallazgos destacados del informe posterior

El archivo informe_zap_despues.html muestra cuatro tipos de alerta de riesgo medio, todos relacionados con la política Content Security Policy (CSP):

  • CSP: Failure to Define Directive with No Fallback. ZAP señala que falta la directiva form-action, que no hereda automáticamente de default-src.
  • CSP: Wildcard Directive. Revisar si la política usa comodines más amplios de lo necesario.
  • CSP: script-src unsafe-inline. La política permite scripts en línea; valorar nonces o hashes si la arquitectura lo permite.
  • CSP: style-src unsafe-inline. La política permite estilos en línea; valorar una configuración más restrictiva compatible con la aplicación.

El informe posterior también incluye cuatro tipos de alerta informativa: Information Disclosure - Suspicious Comments, Modern Web Application, Session Management Response Identified y User Agent Fuzzer. Se recomienda revisar el detalle de cada alerta antes de clasificarla como un problema real o como información esperada.

6. Conclusiones

  1. Se documentaron los resultados de ambos archivos HTML de OWASP ZAP en un único informe.
  2. El primer informe registra 12 tipos de alerta y el segundo 8; como el alcance de los informes es diferente, la comparación debe interpretarse con cautela.
  3. En el informe posterior no aparecen alertas de riesgo alto ni bajo; se mantienen cuatro tipos de alerta de riesgo medio asociados a la política CSP y cuatro informativos.
  4. La validación final de las tres cabeceras de seguridad indicadas fue correcta para la respuesta HTTP comprobada.
  5. Los resultados presentados corresponden principalmente a WebEmpresa en localhost:5273. Estos dos informes no acreditan por sí solos una evaluación independiente de la API ApiClientes.

7. Recomendaciones

  • Revisar la política CSP, en especial form-action, el uso de comodines y las directivas script-src y style-src.
  • Conservar ambos HTML originales como evidencia y anotar claramente qué alcance corresponde a cada uno.
  • Si se vuelve a ejecutar un análisis activo, utilizar una copia de seguridad o una base de datos de prueba: un escaneo puede generar solicitudes que creen, modifiquen o eliminen registros.
  • Si el trabajo requiere revisar también el backend, analizar la API ApiClientes por separado en un entorno controlado.
